# 服务器版与本机版

## 产品边界

| 项目 | 职责 |
| --- | --- |
| `blueforst/dsh-toolkit-local` | 额度、费用及对应 UI 的唯一维护源；直接安装到现有 DSH，浏览器与 CUA 全部沿用原生功能 |
| `blueforst/dsh-toolkit` | Linux 整机资源监控、采集服务、原有 Camoufox/Xfce/noVNC/CUA 部署配方，固定复用本机通用功能 |

两个成品各自只安装一个包，不要在同一 DSH profile 同时启用。Magic Context 不属于本次拆分。

## 固定复用，不自动跟随

服务器包包含 `vendor/dsh-toolkit-local` 的生成快照。源码只在本机仓库修改；`vendor/dsh-toolkit-local.source.json` 记录来源仓库、完整提交号、版本与各文件 SHA256。服务器端不运行远程更新器，不在安装时克隆另一个仓库，也不使用 `main` 或 `latest` 作为运行时依赖。

维护者更新流程：

1. 在本机仓库完成改动、测试和提交，切到准备复用的精确提交，保持工作区干净。
2. 在服务器仓库执行 `node scripts/sync-local.mjs --source ../dsh-toolkit-local`。
3. 执行 `npm run build`、`npm run check`，并设置真实 `DSH_ENTRYPOINT` 运行 `npm test`。
4. 检查来源锁、生成快照与客户端产物一起进入服务器提交，再独立发布服务器版本。

`node scripts/sync-local.mjs --check` 校验本地快照完整性；附带 `--source` 可继续核对精确提交的源文件。CI 按来源锁检出本机仓库进行核对，不能手工修改 vendor 后只重算哈希绕过来源检查。

## 部署与回滚

本次迁移不改变服务器包名 `@forst/dsh-toolkit`、费用投影键、用户数据或原有部署配置，不会自动更新正在运行的 DSH。保留旧 `.tgz`、镜像和配置即可继续原版本或回退。

本机安装包不含 Docker、Linux 采集器、Camoufox、noVNC、CUA provider 或浏览器配置。插件安装和卸载只通过 DSH 原生插件机制完成，不改原生浏览器/CUA设置，不删除会话历史。
