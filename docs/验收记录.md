# v0.1.1 浏览器生命周期验收

日期：2026-11-01。延续上述 DSH、Node.js、Pi 与浏览器版本，在独立容器中复用固定浏览器资源；未在本机运行构建或浏览器测试。

- 自动回归 12 项全部通过，其中 7 项覆盖生命周期：默认三十分钟、并发启动、轮询不唤醒、闲置边界、长工具、下载、键鼠续期与唤醒、探测失败保护、手动关闭后恢复、启动失败重试和回收互斥。
- 使用实际 Camoufox、Playwright MCP、MCP SDK 和 Xvfb，闲置时间在测试容器内缩短为 3000 毫秒，加快边界验证；部署默认仍是 1800000 毫秒。
- MCP 初始化和工具列表读取后，浏览器进程为 0。持续轮询标签列表也能回收，全部标签页关闭，浏览器进程归零。
- 同一 HTTP MCP 会话在回收后继续调用成功；持久 Cookie 与设备预设保持一致；旧标签页没有恢复。
- `browser_close` 释放整个实例；持续七秒的工具和七秒的下载均不会在中途被三秒闲置计时器关闭。
- 通过 XTest 向 Xvfb 发送键鼠事件验证桌面操作：空桌面自动唤醒浏览器，持续输入可延后回收，停止输入后按时释放。
- stdio 代理退出后，broker 的 HTTP 会话数归零。最终浏览器进程 0、活动操作 0、标签页 0、MCP 会话 0。

复验脚本为 `tests/browser-integration.mjs`，必须在独立容器设置 `CAMOUFOX_ISOLATED_TEST=1` 执行；它只访问容器内自建的测试网页，不访问生产页面或外部模型。

现有部署已应用浏览器运行时修复，并在部署环境显式配置 `DSH_BROWSER_IDLE_TIMEOUT_MS=1800000`。容器健康检查通过，实际运行时返回该值；启动和工具注册后 `running=false`、`pages=0`、`active=0`。现网使用本地网页完成 MCP 唤醒与 `browser_close` 检查，关闭后浏览器进程归零；公网未登录仍为 401，登录后首页为 200。旧镜像、Compose 和接入源码保留用于回滚。
