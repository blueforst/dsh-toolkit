# 部署与迁移

## 调用关系

侧栏资源 → DSH 认证保护的 `/server-metrics` → 宿主网桥上的采集器。

Go 月额度 → DSH 认证保护的 `/opencode-go-quota` → 官方 Go usage API。多个浏览器共享一分钟缓存，并发请求合并。

会话费用 → 原生 Session Controller → `forstSessionCost` 投影 → 当前 DSH 的 Pi 目录与计算函数。没有新增费用轮询接口。

## 宿主采集器配置

| 配置 | 默认值 | 用途 |
| --- | --- | --- |
| `DSH_METRICS_URL` | Docker 自动网桥；原生环境回环地址 | DSH 服务读取宿主采样的完整 URL |
| 采集器 `DSH_METRICS_BIND` | `127.0.0.1` | 直接运行采集器时的监听地址 |
| 采集器 `DSH_METRICS_PORT` | `9191` | 监听端口 |
| 采集器 `DSH_METRICS_DISK` | `/` | 被统计的磁盘路径 |

安装脚本参数为 `--network`、`--bind`、`--port`、`--disk`，支持 `--dry-run`。修改端口后，也要同步设置 DSH 的 `DSH_METRICS_URL`。

```bash
sudo python3 scripts/install-host-metrics.py --bind 127.0.0.1 --port 9191 --disk /
systemctl status dsh-toolkit-metrics.service
```

Docker 的宿主采集器地址只供容器访问，不需要发布公网端口。客户端通过 DSH 原生认证读取聚合数值。

## 升级 DSH 运行时

1. 停止使用该 DSH 用户目录的进程，备份完整的 `dsh-home` 持久卷和 Compose 配置，并保留原镜像和 Toolkit 安装包。
2. 如果在 profile 的 `package.json` 中手动启用了 `@deepseek-ai/dsh-experimental-tool-worktree`，从 `dsh.profile.bundles` 移除该项。Worktree 已整合进 DSH 原生功能。
3. 用新版 Compose 配方重建所用镜像，启动 DSH `0.2.2-rc.2`，安装 Toolkit `0.2.2` 并重启 Web profile。核对现有会话、资源、Go 月额度和会话费用，以及已启用的桌面和浏览器功能。
4. 需要降级时，停止新版进程，用旧镜像、配置和升级前的 `dsh-home` 备份启动旧版本。

[DSH 发布说明](https://github.com/deepseek-ai/deepseek-harness/releases/tag/dsh-v0.2.2-rc.2) · [容器发布与迁移说明](https://github.com/runzhliu/deepseek-harness-docker/releases/tag/image-v0.2.2-rc.2-r1)

## 旧独立包迁移

1. 备份 `web` profile 的包清单、锁文件和 Cordis 配置。
2. 在模型会话空闲时，移除已安装的两个旧独立包，安装统一 `.tgz`。
3. 保留原有采集器即可；若采集地址不同，用 `DSH_METRICS_URL` 指向它。不要让两个采集器绑定同一地址和端口。
4. 重启 DSH，检查三条资源、月额度和费用入口；打开旧会话核对累计金额。

回滚时移除统一包，重新安装原来的两个版本并重启。持久会话日志不变；费用投影保留原键和结构，既有缓存可继续使用。

## 移除宿主服务

```bash
sudo systemctl disable --now dsh-toolkit-metrics.service
sudo rm /etc/systemd/system/dsh-toolkit-metrics.service
sudo rm /usr/local/libexec/dsh-toolkit-metrics.py
sudo systemctl daemon-reload
```

这些命令只适用于本仓库安装的服务；以前另行安装的采集器由原部署方式管理。
