# 原版大肥鱼动画与 DSH 桌面验收

验收日期：2026-11-03（北京时间）。这是可选集成，代码位于草稿 PR，尚未发布新版 npm 包。

## 原版一致性

固定 `YunYueSama/codex-deepseek-pet` 提交 `7661c8b304c5400701f91da01b1a643a207331de`。170 个文件共 166,791,670 字节逐个通过 Git blob 校验，原始图集、运动场、`motion.js`、`flow.js`、`app.js`、行为、物理及步态模块保持原始字节。由原模块导出的全部 38 个原生动作与运行播放器完全相同；4 个兼容别名不计入原生动作数。

运动场验收实际绘制 `dense-wave:1:3` 的两个不同中间时刻，输出像素不同。结合 `flowRenderer.ready` 与 WebGL 绘制计数，确认运行原版插值，未退回少数姿势切换。原版目标调度为 60 FPS；实际桌面帧率见下方测量，不能用目标值或视频文件帧率代替。

`think` 使用原版 `story-token` 的 0、1、2 帧与 110、130、180 毫秒时序，之后保持末姿势和原版呼吸效果；`happy` 与 `wave` 在该上游版本中共用挥手动作。这些语义保持上游定义。

## 部署与功能

8 GB 机运行完整 Xfce 桌面及原版 Electron 宿主；4 GB 机提供私网状态租约和原版资源。无 GPU，两端不加载本地大模型。Linux 宿主使用 Electron 43.7.6，包含[移动后鼠标穿透失效的官方修复](https://releases.electronjs.org/release/v43.7.6)。桌宠上限为 2 核、2048 MiB，临时文件系统为 512 MiB；CPU 权重较低，让 DSH 在竞争时优先运行。上限不是保留资源。

- 真实桌面显示透明角色，截图检查无矩形底色。
- X11 输入形状为角落的 1×1 区域，思考及走动后仍保持穿透；动作前后焦点相同，角色没有取得焦点。
- 实际模型请求观察到自动思考、工具执行、手动挥手、恢复闲置；不传递思考正文。
- 浏览器预览加载全部 38 个原生动作、8 个常用按钮、原版运动场及 48 秒视频；无前端异常。
- 预览继承 DSH 登录与来源检查；隔离验收确认无登录 401、跨来源请求 403，原始 RGBA 路径不代理。
- 原版 64 项与项目 15 项测试全部通过，0 失败、0 跳过；JavaScript / JSON / Shell、11 个 Python 文件及发布内容检查通过。

预览首次加载约 160 MiB，资源采用浏览器私有缓存。原版宿主在没有运动场时退出，预览显示失败，不静默降级。Windows 专用的前台窗口和窗口边缘探测关闭；原版渲染、物理和行为算法不改。

## 性能与边界

在没有并发测试进程的原版桌宠采样中，8 秒走动的实际绘制约 **28.48 次/秒**、运动场绘制约 28.15 次/秒，窗口移动 251 像素。侧车平均占用 175.84% 单核 CPU，即两核整机约 **87.92%**；工作集约 **890.91 MiB**。5 秒闲置采样约 8.01% 单核 CPU（整机约 4.01%），工作集约 873.21 MiB。闲置时原版会跳过没有姿态变化的重绘，绘制次数不能当作调度帧率。

测量取原版画布实际绘制计数差值，CPU 取侧车 cgroup 累计使用时间差，内存为扣除 inactive_file 的工作集；不使用 requestAnimationFrame 回调频率代替动画帧率。目标调度仍为 60 FPS，未更改素材、运动场或限帧以减负。没有 GPU 的两核主机在密集原版动作下无法保证实时 60 FPS；agent 与浏览器同时工作时还会竞争 CPU。

旧版图片播放器的约 33 MiB 内存及 23% / 41% 双机 CPU 数据仅属[历史记录](2D桌宠验收.md)，不能作为当前原版播放器的资源预算。

## 双机 30 秒真实桌面录制

8 GB 机采集同一真实桌面，经私网传输原始 YUV；4 GB 机以 x264 veryfast 编码 1080p30、6 Mbps。角色按原版步态连续左右走动，没有在编码端重复叠加。解码确认为 30.000 秒、900 帧，文件 22,389,091 字节，AAC 静音轨道。

| 设备 | 整机平均 CPU | 单次最高 CPU | 最低可用内存 |
| --- | ---: | ---: | ---: |
| 8 GB 桌面机 | 93.07% | 100.00% | 5505.29 MiB |
| 4 GB 编码机 | 39.15% | 51.02% | 2824.32 MiB |

采样读取整机 `/proc/stat` 与 `MemAvailable`，100% 表示两核整机满载；两端采样窗口分别为 35 秒及 32 秒，包含采集开始和结束的少量时间。采集期间角色实际绘制约 **20.52 次/秒**，虽录制文件为 30 FPS，不能据此声称动画本身每秒有 30 个新画面。8 GB 机的主要瓶颈是软件渲染 CPU，4 GB 机编码尚有余量，内存充足；并发 agent / 浏览器工作会进一步争用 CPU。这次短测不能证明长时间平台直播稳定性。

## 动作演示

使用原版 Electron 主程序、原版物理步态与原版 `draw`，在隔离运行时按可控时钟逐帧渲染。视频为 H.264、1280×720、60 FPS、48.000 秒、解码 2880 帧，无音轨；制作耗时约 307 秒。13 段覆盖待机、思考、挥手、开心、难过、惊讶、左右走动、跳跃、跳舞、吃东西、入睡及醒来，有限动作完整播放后按原版回到待机。角色画布为原版 600 像素，成片内按版面显示；原素材不缩小或改写。

视频是离线原版动作演示，不能证明服务器实时桌面达到 60 FPS，也不代表平台直播延迟。没有配置 TTS、口型、桌面声音或向 B 站、抖音推流。

所有构建、测试、解码及渲染均在服务器执行。临时凭据在界面测试结束后删除，隔离容器及临时负载文件在证据归档后清理；保留生产服务、回滚备份、来源许可和演示成片。部署、停用与回滚见[角色接入说明](../integrations/png-avatar/README.md)。
