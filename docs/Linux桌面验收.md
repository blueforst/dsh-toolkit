# Linux 桌面验收记录

日期：2026-11-03。基线为 DSH `0.2.2-alpha.2`、Node.js `24.22.1`、Debian 13、Xfce 4.20、Cua Driver `0.28.0`。构建与真实桌面验收均在服务器执行。

## 已验证结果

| 项目 | 证据与结果 |
| --- | --- |
| 项目回归 | 13 项单元回归通过；JavaScript、Shell、JSON 检查和发布内容审计通过；成功打包 `0.1.2` |
| 官方 DSH 接入 | 真实 Cordis、Computer Use、MCP provider 和原生工具执行器发现 60 个工具；卸载测试 provider 后释放注册 |
| 无障碍与截图 | X11、AT-SPI 可用；真实编辑器窗口返回无障碍树和 PNG；输入后独立状态读回文字，保存后的文件内容一致 |
| 截图坐标路径 | 在独立干净桌面中关闭无障碍树观察，依据已核对的 640×480 编辑器截图，在 `(320, 240)` 点击；输入及保存均携带像素坐标；文件读回 `DSH_VISION_ONLY_CUA_OK`，并保留前后截图 |
| 浏览器兼容 | 快捷方式启动现有 broker 的 Camoufox；Browser Use 可用；释放后 Cookie 与设备预设不变；显式关闭释放进程 |
| 桌面活动 | 编辑器键鼠操作不唤醒浏览器；三十分钟配置读回正确，回收与活动保护策略通过单元回归 |
| Web UI | 中文入口为“桌面”，使用显示器图标；弹窗和 iframe 标签同步修改；真实 noVNC 连接，画面为 1440×900；未发现前端异常 |
| 生产入口 | 通过既有 HTTPS 和登录入口打开完整桌面；未登录请求返回 401；容器健康检查通过 |
| 容量 | 约 8 GB 宿主机上，空闲 DSH 完整容器约 830 MiB；在线提高到 6 GiB 内存上限和 7 GiB 内存加 swap 总上限，保持健康且未重启 |

截图坐标测试没有使用元素句柄定位。工具内部仍可能使用平台无障碍或键盘输入实现；这里验证的是模型可以只依据截图选择坐标并完成操作。测试通过 DSH 官方工具执行器发起，不把它表述为真实模型已完成任意应用的自主视觉任务。截图质量与模型路由的图像接收能力应分别验证。

Xvfb 下的像素输入使用已授权的专用桌面前台模式。无障碍元素操作可走后台路线；不承诺所有应用都支持后台像素输入。真实三十分钟等待没有在本次重复执行，配置和回收策略分别进行了读回与回归验证。

生产切换前已备份 Compose、原镜像标识及持久数据，并准备恢复旧镜像的脚本。首次切换暴露了社区入口脚本对参数顺序的限制，自动回滚后将所有 `--patch` 移到 CLI 参数之前，再次切换成功。重建保留既有会话、工作文件及浏览器配置。

配方和复现命令见 [Linux 桌面说明](../integrations/linux-desktop/README.md)。
